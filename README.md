## 🔴 تازه در ۱۳٫۰ — چرا هیچ اردری باز نمی‌شد

مسیرِ ارسالِ اردر **هرگز نمی‌توانست کار کند**. چهار اسمی که `place()` و
`manage_open_positions()` صدا می‌زدند — `split_volume`، `_filling`،
`_retcode` و `LADDER` — هیچ‌جا تعریف نشده بودند. پایتون اسمِ گلوبال را موقعِ
**اجرای خط** پیدا می‌کند نه موقعِ لود شدنِ فایل، برای همین ربات بالا می‌آمد،
زون پیدا می‌کرد، `SIGNAL` چاپ می‌کرد — و روی اولین ستاپی که به حجم‌گیری
می‌رسید `NameError` می‌داد. هر گزارشِ «اردر باز نشد» به همین‌جا برمی‌گردد.
مسئله سخت‌گیریِ قوانین نبود.

سه ایرادِ دیگر در همان مسیر:

- **سه اردرِ یکسان روی یک قیمت.** `sync_orders` قیمتِ خودش را با دقتِ `1e-6`
  با بروکر مقایسه می‌کرد. موتور لبه‌ی خامِ زون را دارد (`4650.3847`) و بروکر
  همان را روی digits نماد گرد کرده نگه می‌دارد (`4650.38`) — پس تطبیق
  **همیشه** شکست می‌خورد و اردر هر کندل دوباره فرستاده می‌شد.
- **زونی که برای همیشه قفل می‌شد.** موتور پُر شدنِ اردر را از روی کندل
  شبیه‌سازی می‌کند؛ این در بک‌تست درست است و در حالت زنده خطرناک: وقتی ارسال
  شکست می‌خورد، موتور بازهم معامله‌ی خیالی‌اش را باز می‌کرد و آن زون تا آخر
  عمرش قفل می‌شد. همان کنسولی که می‌گفت `0 order(s), 0 position(s)` ولی
  `BLOCKED: already has an order or a running trade`. حالا `reconcile()` هر
  کندل دفترِ موتور را با بروکر یکی می‌کند، در هر دو جهت.
- **انقضای ناهماهنگ.** ۴۰ کندل در ربات مقابلِ ۱۰ کندل در موتور.

**استاپ دیگر از سه کندلِ آخر خوانده نمی‌شود، از لبه‌ی خودِ زون خوانده می‌شود.**
اندازه‌گیری روی XAUUSD واقعی با اسپردِ ۱۴ سنت: مجموع **+۰٫۰۳۷ → +۰٫۰۵۰R**
روی ۳۶۳۲ معامله، و M5 از **+۰٫۱۰۲ به +۰٫۱۳۶R**.

هر دو اندیکاتور (Pine و MQ5) هم دقیقاً همین تغییرات را گرفتند، و در هر دو
`sigTouch` با مقدارِ ۰ ساخته می‌شد — یعنی برابرِ تعدادِ تاچِ یک زونِ تازه، پس
**هیچ زونی هرگز اردر نمی‌گرفت**. حالا از ‎-۱ شروع می‌شود.

## 🩺 تازه در ۱۵٫۰ — چرا آن دو معامله ضرر دادند

از لاگِ زنده‌ی خودت، سه چیزِ جدا:

**۱) هم‌زمان سه معامله باز می‌کرد.** `max_open` روی ۳ بود — در حالی که همین
فایل جمله‌ی کتاب را نقل می‌کرد: «تا معامله‌ای باز است، سیگنالِ جدید نگیر».
سه معامله‌ی هم‌زمان یعنی سه بار اشتباه کردن دربارهٔ **یک** بازار در **یک**
لحظه. در لاگِ تو دو تا BUY پشتِ سرِ هم باز شد (۱۲:۲۸ و ۱۲:۲۹) در حالی که
قیمت از ۴۶۲۹٫۹۶ داشت می‌آمد پایین به ۴۶۲۴٫۵۲. حالا **یکی**:

| | ۳ تا هم‌زمان | **۱ تا** |
|---|---|---|
| مجموع | ‎+۰٫۱۲۹R | **‎+۰٫۱۶۲R** |
| M1 | ‎+۰٫۰۶۰ | **‎+۰٫۰۸۲R** |
| M5 | ‎+۰٫۲۴۲ | **‎+۰٫۲۸۷R** |
| M15 | ‎+۰٫۲۰۱ | **‎+۰٫۲۷۸R** |
| H1 | ‎+۰٫۱۹۹ | **‎+۰٫۳۶۸R** |

**۲) `retcode 10019: not enough free margin`.** ریسک و مارجین دو سقفِ جدا
هستند و فقط ریسک چک می‌شد. حسابِ ‎$۱۰۴ با دو پوزیشنِ ۰٫۰۱ لاتِ طلا حدودِ
‎$۱۲ مارجینِ آزاد دارد و طلا حدودِ ‎$۴۶ برای هر ۰٫۰۱ لات می‌خواهد — پس
سومی رد می‌شد **بعد از اینکه موتور معامله‌اش را باز کرده بود**. حالا قبل از
ارسال از بروکر پرسیده می‌شود.

**۳) «ربات لحظه‌ای باید چک کنه».** حلقه از ۵ ثانیه به **۱ ثانیه** آمد، و
تا وقتی معامله باز است یک خطِ زنده می‌نویسد:

```
live · BUY from 4627.29 · now 4628.90 · P/L +1.61 · 2.29 to the stop, 5.96 to target
```

> استاپ و تارگت **روی خودِ بروکر** هستند، پس تیک‌به‌تیک اجرا می‌شوند و به این
> حلقه کاری ندارند. چیزی که این‌جا تصمیم گرفته می‌شود بریک‌ایون و ratchet است.
> **ورود** عمداً روی کندلِ بسته می‌ماند: زون‌ها، ATR و شمارشِ تاچ همه از کندلِ
> تمام‌شده ساخته می‌شوند، و تصمیم‌گرفتن از نصفِ کندل یعنی معامله‌کردنِ چیزی که
> هیچ‌وقت اندازه‌گیری نشده.

## 🎯 تارگت روی ۲R (پیش‌فرض از ۱۹٫۰) و اسکلپِ ۱۰ ثانیه‌ای

سود حالا روی **۲ برابرِ استاپ** برداشته می‌شود. این انتخابِ توست نه نتیجه‌ی
اندازه‌گیری — ۳R در هر چهار ستون بهتر است — ولی ۲R **سریع‌ترین مقداری است که
هنوز در همه‌ی آن‌ها مثبت است** و حدود نیم‌برابر بیشتر معامله می‌برد:

| تارگت | M1 آموزش | M1 آزمون | M5 آموزش | M5 آزمون | نرخ برد |
|---|---|---|---|---|---|
| ۰٫۷۵R | ‎-۰٫۰۴۶ | ‎-۰٫۱۴۲ | ‎-۰٫۰۳۸ | ‎+۰٫۰۷۵ | ۵۳–۶۳٪ |
| ۱٫۰R | ‎-۰٫۰۵۱ | ‎-۰٫۱۰۳ | ‎-۰٫۰۳۵ | ‎+۰٫۰۷۹ | ۴۹–۵۵٪ |
| ۱٫۵R | ‎+۰٫۰۳۸ | ‎+۰٫۰۰۵ | ‎+۰٫۰۸۵ | ‎+۰٫۱۹۹ | ۳۵–۴۰٪ |
| **۲٫۰R** | **‎+۰٫۰۸۹** | **‎+۰٫۰۳۶** | **‎+۰٫۱۵۰** | **‎+۰٫۲۸۱** | **۲۵–۳۳٪** |
| ۳٫۰R | ‎+۰٫۱۴۵ | ‎+۰٫۰۹۶ | ‎+۰٫۲۵۷ | ‎+۰٫۳۶۷ | ۱۷–۲۳٪ |

هر عددِ دیگری: `LIVE_5m.bat --tp 3`

### اسکلپِ ۱۰ ثانیه‌ای — `LIVE_10s.bat`

MT5 تایم‌فریمِ زیر یک دقیقه ندارد، پس این کندل‌ها از **تیک** ساخته می‌شوند.
آن بخش تست شده و کار می‌کند. ولی این تنها چیز در کلِ پروژه است که **پشتش
اندازه‌گیری نیست** — دیتای ۱۰ ثانیه‌ای وجود ندارد.

آنچه *می‌شود* حساب کرد:

- استاپ در ۱۰ ثانیه ≈ **‎$۰٫۷۹** (از برازشِ `stop = 2.23 × minutes^0.58`)
- اسپردِ ‎$۰٫۱۴ = **۱۸٪ از R هر معامله**
- با تارگتِ ۲R، برای سربه‌سر شدن **۳۹٪ نرخ برد** لازم است
- M1 — سریع‌ترین تایم‌فریمی که اندازه‌گیری شده — روی ۲R **۲۵–۲۷٪** می‌برد

و کوچک‌تر کردنِ تارگت بدترش می‌کند نه بهتر: تارگتِ کوچک‌تر اسپرد را کم
نمی‌کند، پس نرخِ بردِ لازم را **بالا** می‌برد.

گاردِ اسپرد در این لانچر روی ۲۵٪ گذاشته شده وگرنه هیچ معامله‌ای نمی‌گیرد.
این اجازه‌ی معامله می‌دهد، نه سودآوری. ربات کلِ این حساب را موقع بالا آمدن
چاپ می‌کند و منتظر Enter می‌ماند.

## ⚡ ورودِ مارکت به‌جای اردر لیمیت (پیش‌فرض از ۱۴٫۰)

حالا ربات **همان لحظه‌ای که ستاپ چاپ می‌شود وارد می‌شود**، روی کلوزِ همان
کندل — نه اینکه اردر لیمیت روی زون بگذارد و منتظرِ پول‌بک بماند.

انتظار داشتم این بدتر باشد (استاپ پهن‌تر، تارگت نزدیک‌تر). **اشتباه می‌کردم.**
اندازه‌گیری روی دیتای واقعی، به ازای هر معامله:

| تایم‌فریم | لیمیت (کتاب) | مارکت | |
|---|---|---|---|
| M1 | ‎+۰٫۰۱۳R | **‎+۰٫۰۶۰R** | |
| M5 | ‎+۰٫۲۰۶R | **‎+۰٫۲۴۲R** | |
| M15 | ‎+۰٫۰۸۲R | **‎+۰٫۲۰۱R** | |
| M30 | ‎+۰٫۰۹۶R | **‎+۰٫۱۹۸R** | |
| H1 | **‎-۰٫۰۷۰R** (ضرر) | **‎+۰٫۱۹۹R** | از ضرر به سود |

**چرا؟** اردرِ لیمیت فقط وقتی پُر می‌شود که قیمت به زون **برگردد** — و بخشِ
خوبی از دفعات برمی‌گردد چون زون دارد **می‌شکند**. پس لیمیت روی بازنده‌ها
انتخاب می‌شود، و ستاپ‌هایی که از همان اول جواب دادند اصلاً پُر نمی‌شوند.

**هزینه‌اش را هم باید گفت:** استاپ پهن‌تر می‌شود (قیمت هنوز به زون نرسیده،
ولی استاپ باید آن‌طرفِ زون بماند)، پس حسابِ کوچک تعدادِ کمتری از آن‌ها را
می‌تواند بردارد. روی M5 با **‎$۱۰۴**:

| | تعداد معامله | هر معامله | مجموع |
|---|---|---|---|
| لیمیت | ۹۱ | ‎+۰٫۷۲۰R | **‎+۶۶R** |
| مارکت | ۴۲ | ‎+۰٫۲۶۶R | ‎+۱۱R |

یعنی **روی موجودیِ فعلیِ تو لیمیت هنوز مجموعِ بیشتری می‌دهد**، چون تعدادِ
خیلی بیشتری ستاپ زیرِ سقفِ ریسک جا می‌شود. مارکت وقتی برنده می‌شود که
موجودی به استاپ‌های پهن‌تر اجازه بدهد.

برگرداندن به روشِ کتاب، هر وقت خواستی:

```
LIVE_5m.bat --limit
```

## 💵 ربات دیگر به موجودی کار ندارد — و عددِ واقعی

از نسخه‌ی ۱۸، ربات **هیچ ستاپی را به‌خاطر موجودی رد نمی‌کند**. قبلاً یک سقفِ
ریسک داشت که روی حسابِ ‎$۵۶ باعث می‌شد M5 **صفر** معامله از ۵۸۰ ستاپ بگیرد.
حالا هر ستاپ با کوچک‌ترین حجمِ بروکر می‌رود بیرون و ریسکش **نمایش داده
می‌شود** به‌جای اینکه جلویش گرفته شود:

```
> BUY  RBS  @ 4627.29  stop $5.06 =  !! 9.0% of the account · 2.7R to TP1
```

برگرداندنِ سقف، هر وقت خواستی: `LIVE_5m.bat --risk-cap 3`

### ولی یک سقفِ دیگر هست که مالِ من نیست

روی XAUUSD استاندارد، **یک پوزیشنِ ۰٫۰۱ لات حدودِ ‎$۴۶ مارجین می‌خواهد**
(اهرم ۱:۱۰۰). یعنی حسابِ ‎$۵۶ فقط **‎$۱۰ با نقطه‌ای فاصله دارد که دیگر
هیچ معامله‌ای نمی‌تواند باز کند** — دو معامله‌ی ضررده کافی است.

این را اندازه گرفتم، حدس نزدم. همان معامله‌های هولداوت، ۲۰۰۰ بار با ترتیبِ
تصادفی:

| | M1 | M5 |
|---|---|---|
| مسیرهایی که **نتوانستند ادامه دهند** | **۵۰٫۲٪** | **۴۴٫۲٪** |
| موجودیِ پایانی — میانه | ‎$۴۶ | ‎$۴۰۶ |
| موجودیِ پایانی — بدترین ۵٪ | ‎$۴۳ | ‎$۴۱ |
| بیشترین افت — میانه / صدکِ ۹۵ | ۲۸٪ / ۴۸٪ | ۲۶٪ / ۴۹٪ |

مسیرِ واقعیِ تاریخی خوب بود (M1 به ‎$۱۹۱، M5 به ‎$۴۰۶) — ولی **آن یک مسیرِ
خوش‌شانس بود**. با همان معامله‌ها و ترتیبِ متفاوت، نزدیک به **نیمی از
مسیرها** قبل از اینکه لبه فرصتِ مرکب‌شدن پیدا کند به کفِ مارجین می‌خورند.

لبه واقعی است و مثبت. چیزی که در ‎$۵۶ گلوگاه است، تنظیماتِ ربات نیست —
این است که یک پوزیشنِ طلا ‎$۴۶ مارجین می‌خواهد.

> **دمو یا واقعی را حسابی که MetaTrader با آن لاگین است تعیین می‌کند، نه
> اینکه روی کدام فایل کلیک کرده‌ای.** ربات هر بار چاپ می‌کند کدام است و
> قبل از ارسالِ هر چیزی منتظرِ Enter می‌ماند.

### 🔴 تازه در ۹٫۰ — هر زون، اردر خودش؛ تارگت، زون بعدی
این همان ساختاری است که کتاب می‌کشد و تو خواستی: زون‌ها روی چارت روی هم
چیده می‌شوند، **روی هر زون یک اردر لیمیت** می‌نشیند، و **تارگتِ هر اردر،
زون بعدی** است.

نسخه‌های قبلی **یک** معامله در هر زمان داشتند با تارگت ۱R — یعنی بیشترِ
زون‌ها اصلاً اردری نمی‌گرفتند و تارگت هیچ ربطی به چارتِ جلوی چشمت نداشت.

| | قبل | **۹٫۰** |
|---|---|---|
| اردر | یک معامله در هر زمان | **هر زون، اردر خودش** (تا سقف `maxOpen`) |
| ورود | منتظر کندل تأیید، بعد لیمیت | **لیمیت روی زون، قبل از رسیدن قیمت** |
| TP1 | ۱ برابر استاپ | **زون بعدی** |
| TP2 / TP3 | ۲R / ۳R | **زون بعدی‌تر / بعدی‌ترین** |
| اگر زون بعدی نبود | تارگت ۱R می‌ساخت | **اردری گذاشته نمی‌شود** — «No Setup, No Trade» |

نتیجه روی دیتای واقعی خودت، با پرشدن صادقانه (لیمیت فقط در کندلِ **بعد** پر
می‌شود، و در کندل ورود فقط استاپ بررسی می‌شود):

| تایم | سیگنال | برد | انتظار |
|---|---|---|---|
| M1  | ۲۶۷۶ | ۳۹٪ | −۰٫۱۸R |
| M5  | ۱۲۳۱ | ۴۲٪ | −۰٫۰۹R |
| M15 | ۳۸۷ | ۳۸٪ | −۰٫۱۳R |
| M30 | ۱۸۷ | ۴۲٪ | −۰٫۰۶R |
| H1  | ۱۱۰ | ۴۷٪ | **+۰٫۱۳R** |
| H4  | ۲۱ | ۴۷٪ | −۰٫۰۲R |

میانه **−۰٫۰۷R** در برابر **−۰٫۱۸R** مدل تک‌معامله‌ای. بهتر شد — ولی هنوز
سودده نیست و **اسپرد حساب نشده**. فیلترها را هم تک‌تک تست کردم: خاموش‌کردنِ
هرکدام (فیلتر روند، گاردِ لیکوییدیتی، پهنای استاپ) نتیجه را **بدتر** می‌کند،
یعنی هر قانون دارد کارش را می‌کند.

### تازه در ۸٫۰ — قانونی از کتاب که هرگز پیاده نشده بود
بخش لیکوییدیتی کتاب: «در طلا معمولاً اول لیکوییدیتی **سمت فروش** خورده می‌شود
و بعد حرکت اصلی (~۸۰٪)».

روی دیتای واقعی خودت این دقیقاً اتفاق افتاده بود: چارت ۴ ساعته در کف **۳۹۴۳**
(کندل ۷۵۷) یک سیگنال **SELL** داد در کندل ۷۶۱ — یعنی **۴ کندل بعد از کف** — و
بعدش بازار **۶۰۰ دلار بالا** رفت. همان «فلش اشتباه» که می‌گفتی.
حالا فروش درست بعد از زدنِ کف تازه (و خرید بعد از سقف تازه) بلاک می‌شود.

### تازه در ۷٫۴
- **زون‌های غول‌پیکر کوچک شدند.** روی ۴ ساعته باندهای **۲۸۷ دلاری** کشیده
  می‌شد چون سقف ارتفاع زون ۱ ATR بود. اندازه‌گیری نشان داد ارتفاع زون تقریباً
  هیچ اثری روی نتیجه ندارد، پس فقط برای خوانایی **۰٫۴ ATR** شد.
- **پنل دیگر معامله‌ی مالِ ۲۲۵ کندل پیش را «Position» نمی‌گوید** — می‌نویسد
  `— no active setup —`.
- **جفت‌شدن زون‌ها کمی بازتر شد** — سیگنال بیشتر و نتیجه‌ی کمی بهتر.

وین‌ریت: **M1 ۹۶٪ · M5 ۹۳٪ · M15 ۹۱٪ · M30 ۹۷٪ · H1 ۹۳٪ · H4 ۱۰۰٪** (میانگین ۹۵٫۲٪).

### تازه در ۷٫۳ — چرا سیگنال قدیمی می‌ماند
معامله‌ای که به **بریک‌ایون** رسیده بود همچنان جلوی سیگنال بعدی را می‌گرفت تا
تایم‌اوت ۳۰۰ کندل. روی ۴ ساعته **همه‌ی** معامله‌ها به آن تایم‌اوت می‌خوردند —
برای همین پنل می‌نوشت `Last signal: 285 bars ago`.
کتاب ص۴۱ می‌گوید در تارگت اول پول را برمی‌داری و بریک‌ایون می‌کنی، یعنی ستاپ
**تمام شده**. حالا معامله‌ی بی‌ریسک جلوی سیگنال بعدی را نمی‌گیرد.

| تایم | سیگنال در ۷٫۲ | **سیگنال در ۷٫۳** |
|---|---|---|
| M5 | ۳۴۰ | **۵۵۷** |
| M15 | ۱۰۴ | **۱۸۹** |
| H1 | ۲۵ | **۴۰** |
| H4 | ۳ | **۹** |

وین‌ریت هم پایین نیامد: میانگین **۹۴٫۸٪** (M1 ۹۶٪ · M5 ۹۵٪ · M15 ۹۲٪ ·
M30 ۹۵٪ · H1 ۹۱٪ · H4 ۱۰۰٪). ضمناً TP2/TP3 دیگر نمی‌توانند صدها دلار دورتر
بیفتند، و معامله‌ی بسته‌شده فقط ۱۰۰ کندل روی چارت می‌ماند نه ۵۰۰.

### تازه در ۷٫۱ — چرا سیگنال جدید نمی‌آمد
| مشکل | علت | تصحیح |
|---|---|---|
| پنل می‌نوشت `Zones: 0` و پوزیشن مالِ دو هفته پیش بود | قانون «زون فقط از جفت سوئینگ» زون‌ها را خفه کرده بود — به‌طور میانگین فقط **۲ زون** زنده به‌جای ۸ | کتاب ص۲۴ **روش پنجم** را هم دارد: «اگر جفتی نبود، از انگالف زون بکش». حالا سوئینگ بی‌جفت هم زون می‌سازد، منتها **FRESH** |
| `0 @ 240` روی چارت ۱ ساعته | فاصله‌ی دو سوئینگ ۴ ساعته با شماره‌ی کندلِ **چارت** حساب می‌شد | حالا با شماره‌ی کندلِ **تایم تحلیل** |
| استاپ خیلی زود می‌خورد | استاپ نیم ATR بیرون لبه‌ی زون بود؛ کتاب می‌گوید استاپ **روی لیکوییدیتی** است | استاپ پیش‌فرض ۴ ATR — وین‌ریت از ۳۷٪ به **۵۴٪** و ضرر از −۰٫۱۶R به −۰٫۰۲R |
| وین‌ریت پایین | — | تیک **`حالت وین‌ریت بالا (~۹۲٪)`** (با هشدارش بالا) |

### تازه در ۷٫۰ — چیزهایی که از خواندن تک‌تک ۵۷ عکس عوض شد
| صفحه‌ی کتاب | قانون | قبلاً | حالا |
|---|---|---|---|
| ص۲۴ | زون = باندی که **دو** نقطه‌ی هم‌قیمت را در بر می‌گیرد (S+S · R+R · S+R · R+S) | هر پیوت یک زون می‌شد | زون فقط از **جفت** سوئینگ کشیده می‌شود و چون همان دو حرکت را دارد، از اول **VALID** به دنیا می‌آید |
| ص۴۷ | شکستی که برگردد **FBA** است، یعنی زون خوب | یک شکست ⇒ زون فوراً برعکس می‌شد | شکست باید ۳ کندل **دوام بیاورد**؛ اگر قیمت برگردد برچسب **FBA** می‌گیرد |
| ص۴۱/۴۲ | اردر **لیمیت** روی زون، استاپ کمی بیرونش، TP1 خط **۱:۱** | ورود روی کلوز کندل تأیید (استاپ به پهنای کل زون + کندل) | اردر لیمیت روی **لبه‌ی نزدیک** زون، TP1 دقیقاً ۱R — و اردر فقط در کندل **بعدی** پر می‌شود |
| ص۵۱ | GAP هم یک نوع زون است | نداشت | همان جفت‌های **S+R / R+S** |
| ص۱۴ | زون کوچک **داخل** زون بزرگ | بررسی نمی‌شد | گزینه‌ی `requireNested` (پیش‌فرض خاموش) |

### ⚠ مهم — دو دسته زون هم‌زمان (از نسخه‌ی ۶.۰)
کتاب صفحه‌ی ۴۱: «این سِل‌زون و بای‌زون را روی **تایم ۱ ساعته** مشخص کردیم، بعد می‌رویم روی **۵ دقیقه** تأیید بگیریم. تارگت اولمان **۵ دقیقه‌ای** است و دومی **۱ ساعتی**.»
صفحه‌ی ۴۴: «تارگت اول از تایم ۵ دقیقه، تارگت دوم از ۱ ساعته.»

یعنی زون‌ها روی **هر دو تایم با هم** کشیده می‌شوند:

| دسته | از کجا | نقشش |
|---|---|---|
| زون‌های **خودِ چارت** (کادر نازک) | تایم‌فریمی که باز کرده‌ای | ورودهای تایم پایین + **TP1** |
| زون‌های **تایم تحلیل** (کادر ضخیم، با برچسب تایم) | یک پله بالاتر روی نردبان `{15m, 1H, 4H, D, W}` | **روند** (Trend is King) + **TP2** |

| چارت | تایم تحلیل |
|---|---|
| 1m / 5m | 15m |
| 15m / 30m | 1H |
| 1H | 4H |
| 4H | Daily |
| Daily | Weekly |

نتیجه‌ی طبیعی‌اش همان چیزی است که خواسته بودی: تایم پایین سیگنال بیشتر، تایم بالا کمتر. اندازه‌گیری روی همان ۸۳ روز دیتای واقعی XAUUSD: **M1 ۷۵۹ سیگنال · M5 ۳۲۹ · M15 ۱۰۳ · M30 ۵۶ · H1 ۳۰ · H4 ۴**.

## ۲) نصب اندیکاتور در MT5 و اجرای ربات
راهنمای کامل قدم‌به‌قدم: [`docs/MT5_SETUP.md`](docs/MT5_SETUP.md)

خلاصه‌اش: `mt5/SNRZ_Indicator.mq5` را در `MQL5\Indicators` کپی کن، در MetaEditor با `F7` کامپایل کن، و از Navigator روی چارت بینداز. ربات پایتون (`bot/mt5_runner.py`) جداست و پیش‌فرض روی `DRY_RUN = True` است — هیچ اردری نمی‌فرستد تا خودت خاموشش کنی.

## ۳) ربات معاملاتی — پیشنهاد زبان و معماری

### ✅ پیشنهاد: **Python**
برای این استراتژی (سیگنال روی کندل بسته، نه HFT) پایتون بهترین انتخاب است:

| دلیل | توضیح |
|---|---|
| اتصال به MT5 | پکیج رسمی `MetaTrader5` (روی ویندوز/VPS) |
| اتصال به صرافی‌ها | `ccxt` — بیش از ۱۰۰ صرافی (Binance, Bybit, OKX, …) با یک API |
| بک‌تست و تحلیل | pandas / backtesting.py — سریع‌ترین مسیر برای اثبات استراتژی |
| نوتیفیکیشن | python-telegram-bot برای گزارش لحظه‌ای معاملات |
| یک منطق، همه‌جا | فایل `bot/snrz_core.py` همان منطق اندیکاتورهاست؛ MT5 و صرافی هر دو از آن استفاده می‌کنند |

سرعت پایتون اینجا محدودیت نیست چون تصمیم‌ها روی **کندل بسته‌ی M15** گرفته می‌شوند نه میکروثانیه. (اگر روزی سراغ HFT رفتی، آن موقع Rust/C++ منطقی می‌شود — برای SNRZ لازم نیست.)

### معماری
```
bot/
├── snrz_core.py        # موتور زون‌ها: Valid S/R، قانون ۷۵٪، Inversion، PO2  (بدون وابستگی)
├── mt5_runner.py       # اجرای زنده روی MT5 (طلا/فارکس) + مدیریت ریسک ۱٪
├── exchange_runner.py  # اجرای زنده روی صرافی کریپتو با ccxt (پیش‌فرض: DRY_RUN)
└── requirements.txt
```

### بک‌تست
```bash
python bot/snrz_core.py candles.csv     # فهرست سیگنال‌ها — ستون‌ها: time,open,high,low,close
python bot/backtest.py  candles.csv     # نتیجه‌ی هر ستاپ: TP1/TP2/TP3 · BE · SL · وین‌ریت · انتظار R
python bot/backtest.py --synthetic      # مقایسه‌ی قوانین روی داده‌ی ساختگی
```

**برای تنظیم دقیق قوانین به دیتای واقعی نیاز است.** از TradingView روی چارت XAUUSD منوی `⋮` بالای چارت ← **Export chart data** را بزن و CSV را به `backtest.py` بده. داده‌ی ساختگی چون اصلاً حمایت/مقاومت واقعی ندارد، هیچ استراتژی S/R روی آن سود نمی‌دهد؛ فقط برای این خوب است که ببینیم یک فیلتر جدید سیگنال‌ها را خفه نکرده باشد.

### اجرای زنده
```bash
pip install -r bot/requirements.txt
python bot/exchange_runner.py    # کریپتو (اول DRY_RUN=True بگذار)
python bot/mt5_runner.py         # MT5 — فقط روی ویندوز/VPS با ترمینال باز
```
